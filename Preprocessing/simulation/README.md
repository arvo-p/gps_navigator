# GPS Embedded System Simulation (C + Raylib)

A high-performance GPS map visualization and algorithm simulation written in **C99** with **Raylib**.

This project serves as the PC simulation environment for testing embedded GPS algorithms before deploying to microcontroller hardware (e.g. ARM Cortex-M, ESP32, STM32 with ST7789 or ILI9341 displays).

---

## 🏛 Architecture & Code Separation

To ensure clean portability to embedded hardware, the codebase strictly separates **universal core algorithms** from **GUI/Platform rendering**:

```
simulation/
├── include/
│   ├── geo_math.h            <-- [UNIVERSAL] Pure C: WGS84, Mercator, Haversine, Bearing, Tile math
│   └── map_camera.h          <-- [UNIVERSAL] Pure C: Viewport calculations, camera panning, visible tiles
├── src/
│   ├── geo_math.c            <-- [UNIVERSAL] Independent of raylib, OS, or windows.h
│   ├── map_camera.c          <-- [UNIVERSAL] Independent of raylib, OS, or windows.h
│   ├── tile_cache.h          <-- [PRESENTATION] Raylib LRU Texture Cache
│   ├── tile_cache.c          <-- [PRESENTATION] Raylib PNG texture loader & VRAM manager
│   ├── ui.h                  <-- [PRESENTATION] Raylib UI, text boxes, and HUD
│   ├── ui.c                  <-- [PRESENTATION] Interactive widgets & coordinate entry
│   └── main.c                <-- [PRESENTATION] Window loop and rendering
├── tests/
│   └── test_universal_algo.c <-- [TESTS] Automated verification of universal algorithms
├── build.bat                 <-- One-click Windows build script
└── Makefile                  <-- Standard Makefile for MinGW / GCC
```

### 1. Universal Algorithms (`include/geo_math.h`, `include/map_camera.h`)
- **Zero external dependencies**: relies only on C99 standard headers (`<math.h>`, `<stdbool.h>`).
- **Zero dynamic memory allocation in runtime loop**: uses fixed-capacity buffers suitable for embedded microcontrollers with limited SRAM.
- **Portability**: can be copied directly into an embedded firmware project without modification.

### 2. Presentation Layer (`src/tile_cache.c`, `src/ui.c`, `src/main.c`)
- Uses **Raylib** for 60 FPS hardware-accelerated desktop rendering, window events, and input processing.
- Automatically accesses tiles generated by `tile_map_generator.py` in `../tiles/` at zoom levels **12**, **14**, and **16**.
- Implements an LRU cache (default 256 tiles) to prevent VRAM overflow and guarantee smooth panning.

## 🚀 Building & Running

### Prerequisites
- **Linux**: GCC, Make, standard X11 / OpenGL development libraries (`libx11`, `libgl`). Optional: `raylib` from package manager (`sudo pacman -S raylib` or `sudo apt install libraylib-dev`), or uses the bundled `deps/raylib` automatically.
- **Windows**: GCC / MinGW-w64 (e.g. from MSYS2) and Raylib 5.0+.

### Build on Linux
```bash
./build.sh
# or simply:
make
```

### Build on Windows
```cmd
build.bat
# or:
make
```

### Run Simulation
- **Linux**:
  ```bash
  ./gps_simulation
  ```
- **Windows**:
  ```cmd
  gps_simulation.exe
  ```

### Run Core Unit Tests
```bash
make test
```

## 🎮 Controls & Features

### 1. Camera Navigation
- **Arrow Keys (`UP`, `DOWN`, `LEFT`, `RIGHT`)**: Pan the map smoothly.
- **`Shift` + Arrow Keys**: 2.5x fast pan.
- **`W`, `A`, `S`, `D`**: Alternative pan keys (when text inputs are not focused).
- **Mouse Drag**: Click and drag anywhere on the map to pan.
- **On-Screen D-Pad**: Clickable directional buttons in the control panel.

### 2. Zoom Selection
- **Buttons (`Z 12`, `Z 14`, `Z 16`)**: Jump directly to pre-rendered tile levels.
- **`+` / `-` Keys or Buttons**: Step zoom in/out.
- **Mouse Wheel**: Scroll up to zoom in, scroll down to zoom out.
- **Number Keys (`1`, `2`, `3`)**: Quick jump to zoom 12, 14, or 16.

### 3. Coordinate Entry
- Click on **Latitude** or **Longitude** text boxes to edit coordinates.
- Type digits, decimal point, or negative sign.
- Press **`[Tab]`** to toggle between Latitude and Longitude fields.
- Press **`[Enter]`** or click **"Center Map"** to jump to the entered coordinate.
- Click **"Get Current Center"** to copy the current camera position into the input boxes.
- Click any of the **Belgian Location Presets** (e.g., *Liège Center*, *Liège-Guillemins*, *Sart-Tilman*, *Chênée*) to immediately focus on that landmark.

### 4. Telemetry HUD
- Real-time **Latitude / Longitude** in degrees.
- Current **Slippy Tile index** `(X, Y, Zoom)`.
- Physical scale resolution in **meters per pixel**.
- Cache statistics (**hits**, **disk loads**, **active count**).
- Indicator showing whether the camera is inside the pre-rendered Belgian tile area.
