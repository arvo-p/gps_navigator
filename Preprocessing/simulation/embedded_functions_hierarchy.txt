================================================================================
  EMBEDDED GPS NAVIGATION & PATHFINDING LIBRARY — FUNCTION CALL HIERARCHY
================================================================================
Target Platform: Embedded Microcontrollers (ARM Cortex-M0/M3/M4/M7, ESP32, STM32)
Arithmetic:      100% Fixed-Point Integer (Zero float, Zero double)
Memory Model:    100% Static Allocation in .bss / .data (Zero malloc, Zero free)
Standard:        ISO C99 (<stdint.h>, <stdbool.h>)

This document catalogues all functions in the core embedded library, organized
in strict hierarchical order: starting with the most complex high-level
orchestrators (which call multiple subsystems) down to the elementary atomic
leaf functions (which perform direct bitwise/arithmetic operations with zero
or near-zero function calls).

--------------------------------------------------------------------------------
TABLE OF CONTENTS & COMPLEXITY LAYERS
--------------------------------------------------------------------------------
  LEVEL 5: Strategic System Orchestrator (Highest Complexity)
  LEVEL 4: Multi-Phase & Multi-Tile Algorithmic Search Engines
  LEVEL 3: Subsystem Managers (Spatial Cache, Graph Queries, Viewport)
  LEVEL 2: Specialized Data Structures, Fixed-Point Math & Coordinate Projections
  LEVEL 1: Elementary / Atomic Leaf Functions (Zero or Minimal Function Calls)

[5.1] pathfinder_find_route
--------------------------------------------------------------------------------
File:        src/pathfinder.c / include/pathfinder.h
Signature:   bool pathfinder_find_route(Pathfinder *pf, GeoCoord start,
                                        GeoCoord goal, RouteResult *out_route)
Description:
  The master public entry point for navigation routing. It acts as the brain
  of the pathfinding system by evaluating the trip scale and selecting the
  optimal routing strategy:
    - Analyzes Euclidean distance and spatial grid tile adjacency.
    - If distance < 15 km or origin/destination are in the same or adjacent
      0.1° grid cells: executes Mode A (Local Multi-Tile A*).
    - If distance >= 15 km across distant regions: executes Mode B
      (Hierarchical 3-Phase A* using Local -> Highway Backbone -> Local).
    - If hierarchical routing fails (e.g. disconnected local tiles), attempts
      a direct snap onto the high-speed backbone network.
    - If a valid route is discovered, immediately invokes geometry expansion
      to pull detailed road curve points into memory.
Calls:
  - pathfinder_free_route
  - geo_coord_to_grid
  - geo_distance_m
  - is_adjacent_grid
  - run_local_astar
  - run_hierarchical_astar
  - tile_graph_cache_get_backbone
  - tile_graph_snap_node
  - run_backbone_astar
  - pathfinder_load_geometry
Called By:
  - User application / UI navigation controller / Embedded trip executive

[4.1] run_hierarchical_astar
--------------------------------------------------------------------------------
File:        src/pathfinder.c (internal static)
Signature:   static bool run_hierarchical_astar(Pathfinder *pf,
                 GeoCoord start, GeoCoord goal,
                 int32_t start_glat, int32_t start_glon,
                 int32_t goal_glat, int32_t goal_glon,
                 RouteResult *out_route)
Description:
  Orchestrates the 3-Phase Long-Distance Hierarchical A* algorithm:
    Phase 1: Identifies the best local entry gateway node (tagged with
             FLAG_BACKBONE_LINK) in the origin tile and executes local A*
             from start coordinate to the entry gateway.
    Phase 2: Translates the local gateway to the global backbone highway
             network and executes fast Dijkstra/A* transit along motorways
             and primary trunk routes.
    Phase 3: Connects the exit highway gateway node to the local destination
             tile and performs a final local A* run to the exact goal pin.
    Stitches all three route legs together into a contiguous RouteResult.
    Pins origin, destination, and backbone graphs in RAM throughout the
    search to prevent LRU eviction, unpinning them upon completion.
Calls:
  - tile_graph_cache_get_tile
  - tile_graph_cache_get_backbone
  - tile_graph_pin
  - tile_graph_unpin
  - tile_graph_find_gateway
  - tile_graph_snap_node
  - tile_graph_find_matching_node
  - geo_coord_make
  - run_local_astar
  - run_backbone_astar
Called By:
  - pathfinder_find_route


[4.2] run_local_astar
--------------------------------------------------------------------------------
File:        src/pathfinder.c (internal static)
Signature:   static bool run_local_astar(Pathfinder *pf,
                 GeoCoord start, GeoCoord goal,
                 int32_t start_glat, int32_t start_glon,
                 int32_t goal_glat, int32_t goal_glon,
                 RouteResult *out_route)
Description:
  Executes A* search across one or multiple adjacent 0.1° local tiles:
    - Snaps start and goal GPS coordinates to nearest drivable road nodes.
    - Sets up session slots for active tiles, resetting static g-score tables.
    - Uses a 32-bit composite node key (upper 4 bits = tile cache slot, lower
      20 bits = node index within tile) to search across tile boundaries.
    - Drives the binary min-heap priority queue with integer admissible
      under-estimate heuristics (geo_distance_m / 25 m/s).
    - Traverses outgoing edge records, updating tentative g-scores.
    - Reconstructs the complete linked path in reverse from destination to
      origin, accumulating road segment attributes, lengths, and times.

[4.4] pathfinder_load_geometry
--------------------------------------------------------------------------------
File:        src/pathfinder.c / include/pathfinder.h
Signature:   bool pathfinder_load_geometry(Pathfinder *pf, RouteResult *out_route)
Description:
  Resolves intermediate road curves and curvature geometry for an active route:
    - Iterates over all synthesized RouteSegments.
    - Stores the segment start point in out_route->geom_points.
    - For curved edges (geom_count > 0), inspects seg->geom_path, manages the

      directly into the static geom_points array.
    - Appends the segment end point, ensuring a 100% continuous polyline
      ready for visual rendering or navigation heading tracking.
Calls:
  - fopen
  - fclose
  - fseek
  - fread
  - strcmp
Called By:
  - pathfinder_find_route

[2.6] geo_latlon_to_world_point32

File:        src/geo_math.c / include/geo_math.h
Signature:   void geo_latlon_to_world_point32(GeoCoord coord, WorldPoint32 *out_wp)
Description:

    - X axis: linear shift from [-180°..+180°] to [0..2^32 - 1].
